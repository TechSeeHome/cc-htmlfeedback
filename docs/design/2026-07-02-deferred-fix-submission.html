Deferred fix submission design proposal

cc-htmlfeedback widget · 2026-07-02 · branch design/deferred-fix-submission · spec: docs/design/2026-07-02-deferred-fix-submission.md

Today, saving a note and handing it to the agent are one fused action: the moment you press Comment or Strike, the ticket is submitted and the agent starts working. This design separates them: every note is saved as a local draft, and nothing is submitted until you explicitly click Fix (one note) or Fix all (everything pending).

Decision: modeless drafts. No "instant vs. batch" mode switch. The draft state and its Fix button are the UI - what you see is what will (not) be sent. A keyboard fast path (Cmd+Enter = comment & fix now) preserves today's zero-friction single-fix flow.

1 · Flow: current vs. proposed

Current - fused save + submit

  • Select text, type note, press Enter
  • Ticket POSTed instantly; agent wakes and starts fixing
  • Note is now read-only - no way to refine or take it back
  • Agent morphs the page while you are still annotating it
  • Fixes land one by one, possibly conflicting

Proposed - draft, review, then fix

  • Select text, type note, press Enter - saved as a draft
  • Keep annotating a stable page; edit or discard drafts freely
  • Click Fix on one card, or Fix all (3) in the header
  • Only then does the inbox grow and the agent wake
  • Agent sees the whole round of feedback at once
Actor: user agent pain point

3 · Popover mockup

The annotation flow is untouched - Enter saves a comment, Backspace on an empty box saves a strike. Only the hint line changes, and two new shortcuts submit immediately for the quick-single-fix case.

Enter to save draft · Cmd+Enter to fix now · Esc to cancel
Fast path preserved: Cmd+Enter = comment & fix now, Cmd+Backspace = strike & fix now. Today's instant behavior is one modifier away, with no hidden mode to remember.

5 · Why modeless beats a mode switch

1Modes cause errors

A toggle is hidden state, invisible at the moment of annotation - the popover looks identical either way. Users batch when they meant to send, and send when they meant to batch. A visible per-card Fix button is the state: a draft has one, a submitted card has a status pill instead.

2Nothing is sent implicitly

The agent acts only on an explicit user action - the same contract as GitHub's PR review flow, where comments stay pending until "Submit review". Predictable, safe, and a mental model users already have.

3It unifies the widget's two modes

Disconnected mode already works this way: notes accumulate, stay editable, and export via an explicit Copy. Connected mode becomes "disconnected + Fix buttons" instead of a third behavior to learn and test.

4The fast path survives

The one extra click for a quick single fix is erased by Cmd+Enter / Cmd+Backspace. Power users keep today's zero-friction flow; everyone else gets a review step by default.

Bonus, specific to this tool: with instant send the agent live-morphs the DOM while you are still annotating, shifting content and risking lost anchors (re-anchoring is substring-only). Drafts let you annotate a stable page, then hand the whole round over - which also gives the agent full context in one pass instead of sequential, possibly conflicting edits.

6 · Scope and mechanics

  • Widget-only change. Submitting a draft performs exactly today's POST; the inbox file grows only on explicit Fix, so watch-inbox wake semantics still mean "real work arrived". No server, queue, or skill protocol changes.
  • Drafts survive reload via localStorage (per page key), re-anchored on load with the existing reanchor() path.
  • POST failure keeps the draft with an error toast; Fix all submits in order and stops at the first failure.
  • Badge counts drafts + submitted-but-not-done, so pending-but-unsent work is still visible.
  • Out of scope: server-side draft status, draft reordering, editing already-submitted tickets.
